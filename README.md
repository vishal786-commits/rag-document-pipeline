# Aster Policy Assistant — RAG over a UK social housing knowledge base

A **Retrieval-Augmented Generation** system over 36 Aster Group policy documents,
with a FastAPI backend and a Streamlit frontend. Ask a question in plain English
and get an answer grounded only in the policy library, cited to the document and
page it came from.

---

## What makes retrieval work here

**Structure-aware chunking.** PDFs are parsed with `pymupdf4llm` into Markdown, so
headings survive as `#` markers and tables as `|` rows. Headings — not character
counts — decide where chunks break, and Markdown tables are never split mid-table.

**Contextual headers.** Every chunk is prefixed with its heading path before being
embedded:

```
Damp, Mould & Condensation Policy > 2 Policy Statement

2.4 We will arrange an appointment to visit and survey the whole property...
```

Without this, a chunk reading "they must attend within 14 days" carries no
indication of *who* or *which policy*. With it, both the embedding and BM25 see
the section terms.

**Hybrid retrieval.** Pinecone dense search plus BM25 over the whole corpus, fused
with Reciprocal Rank Fusion. Fusion is keyed on the stable vector id rather than
chunk text, so metadata survives — which is what makes citations possible.

**Expired policies are flagged, not hidden.** Eight of the 36 documents are past
their stated review date, five of them building-safety policies. They remain
retrievable, because they are still the operative documents staff are handed, but
any answer that cites one carries a warning computed in code rather than asked of
the prompt.

## Project structure

```
rag-document-pipeline/
├── main.py                  FastAPI: /ask, /health, /policies
├── rag/
│   ├── config.py            every env var and tuning constant
│   ├── catalogue.py         CORPUS_SUMMARY.md parsing, reconciliation, dates, audience
│   ├── loader.py            PDF -> per-page Markdown Documents
│   ├── chunker.py           heading-aware splitting, table preservation, boilerplate
│   ├── ingest.py            CLI: parse -> chunk -> embed -> upsert -> verify
│   ├── retriever.py         dense + BM25 + RRF over Documents
│   └── generate.py          prompt, citations, expiry banner
├── frontend/app.py          Streamlit chat UI
├── knowledge_base/          36 policy PDFs
├── data/kb_chunks.jsonl     chunk snapshot (committed — see below)
├── docs/
│   ├── CORPUS_SUMMARY.md    per-document catalogue; the metadata source of truth
│   └── INGEST_RESULT.md     generated by rag.ingest
└── tests/
```

`data/kb_chunks.jsonl` is committed on purpose. It is the BM25 corpus at runtime
(Pinecone cannot cheaply enumerate a namespace), the input to the offline
evaluation, and a reviewable diff whenever chunking changes.

## API

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/health` | Service and knowledge-base status |
| GET | `/policies` | Every document with audience, status, version, expiry |
| POST | `/ask` | `{question, audience?, status?, doc_id?, history?}` → `{answer, citations, expired_warning, latency_ms}` |

There is no upload endpoint. Conversation history is supplied by the client, so
the service is stateless and works behind more than one replica.

## Tech stack

| Layer | Technology |
|-------|------------|
| LLM | OpenAI `gpt-4.1-mini`, temperature 0, fixed seed |
| Embeddings | OpenAI `text-embedding-3-small` (1536-d) |
| Vector store | Pinecone (cosine) |
| PDF parsing | `pymupdf4llm` → Markdown |
| Chunking | LangChain `MarkdownHeaderTextSplitter` + size guard |
| Sparse retrieval | `rank-bm25`, fitted once at startup |
| Backend / Frontend | FastAPI / Streamlit |

## Running locally

```bash
git clone https://github.com/vishal786-commits/rag-document-pipeline.git
cd rag-document-pipeline
pip install -r requirements.txt
cp .env.example .env        # then fill in the keys
```

The Pinecone index must exist and be **1536-dimensional, cosine**.

```bash
python -m rag.ingest --dry-run   # parse and chunk only, no API calls
python -m rag.ingest --fresh     # embed and upsert
uvicorn main:app --reload
streamlit run frontend/app.py    # http://localhost:8501
```

```bash
python -m pytest                 # no API keys needed
```

### On Windows

The console defaults to cp1252 and will crash on non-ASCII output. Set
`PYTHONUTF8=1` (it is in `.env.example`) or run `chcp 65001` first.

## Known limitations

- **Awaab's Law is not in the corpus.** The four documents covering it were removed
  in the 2026-07-30 corpus reduction, so the assistant correctly declines those
  questions rather than inferring from the Damp & Mould Policy.
- **Audience filtering is effectively inactive.** No remaining document is
  tenant-facing (34 are `staff`, 2 are `reference`), so `audience="tenant"` returns
  only the two government reference documents. The service logs a warning about
  this at startup.
- **Governance tables extract imperfectly.** Cell boundaries in the policy
  governance blocks are sometimes split mid-value, so questions about a policy's
  owner or approver are unreliable. Version and expiry dates come from
  `CORPUS_SUMMARY.md`, not from those tables, and are accurate.
- **`pymupdf4llm` is AGPL-licensed.** Fine for internal deployment; it matters if
  this is ever shipped as a closed-source product.
